## Proposals

### 1. The agent band falls to 140k for every agent carried across a clear

Proposed: keep: a guardrail request. At a `/clear` the harness kills each live agent's foreground command and continues its transcript in a new file under the new session folder, whose first user row is a tool result or a notification, never the brief. The band hook reads only that first row, finds no "context band is Nk" phrase and falls back to 140,000. Eleven agents of this session lost their band that way: the batch-2 builder (brief 327k, hook 140k), batch 4 (229k), a scout at 245k that reported half its findings, the batch-6, 7, 8 and 9 builders (briefs 208k to 301k, the band line five seconds after the clear). Resumed agents also lost their type (a scout became general-purpose and the web gate refused it four times) or their brief. The change: `agent-band.py` resolves the band from the agent's earliest transcript across session folders, or from a per-agent band file the lead writes at spawn, and keys its state by agent, not session. This joins the robot-release request of the same evening (its Change 2 asks for a drawn default instead of the fixed 140k); the mechanism here is new. Until it lands, the lead hands off only when no builder is in a foreground command, or warns each by SendMessage first, and the memory line that blamed the spawn message is corrected (item 12).
